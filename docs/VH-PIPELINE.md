# ValueHunt — Архитектура пайплайна сканирования и оценки вакансий

> **Дата:** 28.06.2026
> **Для:** Владелец продукта и HR (анализ адекватности оценки)
> **Цель:** Понять, как именно работают сканер, UES-оценка и связка между ними — чтобы доверять результатам и знать, где можно влиять.

---

## 1. Общая схема пайплайна

```
HH.ru (веб-сайт)
    │
    ▼
┌─────────────────┐
│  1. SCANNER     │  ← парсинг HTML, без API
│  (scanner.py)   │
└────────┬────────┘
         │ сырые данные (title, description, skills, salary...)
         ▼
┌─────────────────┐
│  2. COLLECTOR   │  ← LLM-анализ: ключевые слова, требования, задачи
│  (collector.py) │
└────────┬────────┘
         │ обогащённые данные (parsed_tasks, parsed_requirements, key_words)
         ▼
┌─────────────────┐
│  3. UES ENGINE  │  ← единая система оценки
│  (ues.py)       │
└────────┬────────┘
         │ результат: score, category, risks, recommendation
         ▼
┌─────────────────┐
│  4. SQLite БД   │  ← сохранение + веб-интерфейс
│  (data/*.db)    │
└─────────────────┘
```

## 2. Компонент 1: Сканер (scanner.py)

### 2.1. Что делает
Парсит сайт **hh.ru** напрямую (без API, через BeautifulSoup). Ищет вакансии по параметрам из `profile.json`.

### 2.2. Откуда берёт параметры поиска

Читает `config/profile.json` → секция `search_filters`:

```json
{
  "regions": ["Россия"],                    // → area=113
  "titles": ["IT project manager", ...],    // → text для поиска
  "salary_from": 250000,                    // → фильтр по ЗП
  "experience": "between1And3",             // → опыт
  "employment": "full",                     // → полная занятость
  "schedule": ["remote", "hybrid"],         // → удалёнка/гибрид
  "search_period": "1",                     // → за последние сутки
  "per_page": "100"                         // → до 100 за запрос
}
```

### 2.3. Процесс сканирования

1. **build_search_params(profile)** — собирает URL-параметры для HH
2. **search_vacancies(params)** — GET-запрос к `hh.ru/search/vacancy`, до 5 страниц по 20 вакансий, с retry (3 попытки)
3. **Парсинг карточки** → `_parse_card()`: hh_id, title, company, salary_from, salary_to, url
4. **Детали** → `get_vacancy_details(url)`: открывает каждую вакансию, парсит:
   - `description` (полное описание)
   - `skills` (ключевые навыки)
   - `work_format` (remote/hybrid/office)
   - `location` (город)
   - `hr_contacts` (контакты HR)
   - `published_at` (дата публикации)
   - `hh_employer_id` (ID компании)
5. **UES-обогащение** → `_enrich_with_ues()` — запускает LLM-анализ + UES-оценку

### 2.4. Регионы

`_resolve_areas()` маппит названия регионов на коды HH:
- `"Россия"` → `"113"`  (вся РФ)
- `"Москва"` → `"1"`
- `"Санкт-Петербург"` → `"2"`

**Было пофикшено:** раньше профиль содержал `"area": 113`, но сканер читал ключ `regions` и игнорировал `area`. Теперь профиль использует `"regions": ["Россия"]`, и код резолвит его корректно.

## 3. Компонент 2: Коллектор / LLM-анализ (collector.py)

### 3.1. Что делает
Запускает LLM (DeepSeek) для извлечения структурированных данных из текста вакансии.

### 3.2. Что извлекает

| Поле | Описание |
|------|----------|
| `key_words` | Массив ключевых слов (для Gate B, для поиска) |
| `parsed_tasks` | Список задач из описания |
| `parsed_requirements` | Список требований |
| `work_format` | Уточнение формата работы |
| `location` | Уточнение локации |

### 3.3. Где используется
- `key_words` — передаются в `UESCalculator.evaluate()` как `resume_keywords` для Gate B
- `parsed_tasks/requirements` — отображаются в UI, не участвуют в скоринге напрямую

## 4. Компонент 3: UES Engine (ues.py) — САМОЕ ВАЖНОЕ

### 4.1. Общая архитектура оценки

```
Вакансия (текст: title + description + skills)
    │
    ▼
┌──────────────┐
│ Шаг 0: БЛОКИ │  ← проверка красных флагов
│ (blocks)     │     если найден → REJECT, score=0
└──────┬───────┘
       ▼ (прошёл блоки)
┌──────────────┐
│ Шаг 1: GATE A│  ← удалёнка, ЗП, локация
│ (gate_a)     │     fail → возможен Override
└──────┬───────┘
       ▼ (прошёл Gate A)
┌──────────────┐
│ Шаг 2: GATE B│  ← архетип роли (01 Enterprise / 03 Product)
│ (gate_b)     │     fail → REJECT (или Override если Gate A тоже fail)
└──────┬───────┘
       ▼ (прошли оба Gate)
┌──────────────┐
│ Шаг 3: ГРУППЫ│  ← 7 групп, ~30 критериев
│ (groups)     │     каждый критерий: keyword-matching по matrix.yaml
└──────┬───────┘
       ▼
┌──────────────┐
│ Шаг 4: ФИНАЛ  │  ← взвешенная сумма → категория S/A/B/C/REJECT
│ (final)       │
└──────────────┘
```

### 4.2. Шаг 0: Блоки (красные флаги)

Проверяются **до** Gate A/B. Если сработал блок — вакансия получает `score=0, category=REJECT` без дальнейшего анализа.

Настроены в `config/ues_config.json` → `blocks`:

| Блок | Цель | Триггеры |
|------|------|----------|
| `ban_gambling` | Гемблинг/букмекерство | "gambling", "betting", "casino", "igaming", "crypto" и т.д. |
| `ban_non_pm_role` | Роль не PM/PO | "team lead", "tech lead", "engineering manager", "CPO" в title |
| `ban_gamedev` | GameDev (не enterprise) | "gamedev", "game development", "игровая студия" и т.д. |

**Режимы проверки:**
- `"target": "title"` — ищет только в заголовке вакансии
- `"target": "full_text"` — ищет во всём тексте (title + description + skills)

### 4.3. Шаг 1: Gate A — Базовые фильтры

Проверяет **три условия**. Если хотя бы одно не пройдено — Gate A fail.

**A1 — Формат работы:**
- Текст проверяется на наличие ключевых слов: "remote", "удален" (ё→е), "wfh", "дистанционно", "hybrid", "гибрид", "смешан"
- Если найдено → pass. Иначе → fail.

**A2 — Зарплата:**
- `min_pass = 200 000 ₽` (проходной порог)
- `target = 250 000 ₽` (целевой порог)
- Если salary_from ≥ min_pass → pass
- Если ЗП не указана → pass (можно предложить свою)
- Если salary_from < min_pass → fail

**A3 — Локация:**
- Если удалёнка или гибрид → pass
- Если город Москва или СПб → pass
- Иначе → fail

**Важно:** Если Gate A fail, но Gate B pass, срабатывает **Override** (см. шаг 3b).

### 4.4. Шаг 2: Gate B — Архетип роли

Проверяет, соответствует ли вакансия одному из двух архетипов:

| Архетип | Ключевые слова |
|---------|---------------|
| `01` — Enterprise PM | "project manager", "pm", "delivery manager", "enterprise", "руководитель проектов", "pmo" |
| `03` — Product PM/PO | "product manager", "product owner", "po", "продукт", "владелец продукта", "pm/po" |

Если **ни один** архетип не совпал → Gate B fail → вакансия REJECT.

*Примечание:* также проверяются ключевые слова из резюме (загруженного через upload-resume). Если резюме содержит слова, совпадающие с текстом вакансии — Gate B pass.

### 4.5. Шаг 2b: Override (High Potential Override)

Если **Gate A fail** + **Gate B pass**:
- Считаются группы (см. шаг 3)
- Проверяется: Company ≥ 6.5 И среднее (role + tech + culture) ≥ 6.0
- Если условия выполнены → Gate A принудительно pass, вакансия получает категорию по полной оценке, рекомендация `apply_terms`

**Зачем:** Если вакансия крутая по содержанию, но не указала ЗП или формат работы — не отбрасывать сразу, а оценить.

### 4.6. Шаг 3: Группы критериев (Scoring Engine)

**Источник:** `config/matrix.yaml` — 7 групп, ~30 критериев, ~230 ключевых слов.

#### 4.6.1. Структура matrix.yaml

```yaml
groups:
  - id: role           # Роль и содержание работы      вес 10
    criteria:
      - id: pm_po_hybrid
        name: Роль PM/PO (гибрид)
        weight: 10     # вес внутри группы
        keywords: ["project manager", "product owner", ...]
      - enterprise_scale    вес 9
      - product_influence   вес 9
      - full_cycle          вес 8

  - id: conditions     # Условия работы               вес 10
    criteria: remote_100, hybrid, office_moscow, business_trips

  - id: finance        # Финансы                      вес 9
    criteria: salary_fix, salary_transparent, it_accreditation, dms

  - id: company        # Компания и репутация          вес 8
    criteria: hh_rating, dream_job, company_age, ceo_media

  - id: career         # Карьера и развитие            вес 8
    criteria: career_ladder, education, mentoring, growth_track

  - id: tech           # Технологический стек          вес 7
    criteria: ai_ml, data_bi_dwh, modern_stack, product_metrics

  - id: culture        # Культура и процессы           вес 7
    criteria: agile_maturity, hiring_transparency, no_outstaff, social_package
```

#### 4.6.2. Как считается критерий

Для каждого критерия:
1. Берутся его ключевые слова из matrix.yaml
2. Текст вакансии нормализуется: `ё → е`, `toLowerCase()`
3. Для каждого ключевого слова проверяется:
   - **Точное совпадение** фразы: `re.search(re.escape(kw), text)`
   - **Если не совпало и фраза длинная (>1 слова)**: проверка, что каждое значимое слово встречается отдельно (например, "удаленная работа" найдёт "работа полностью удаленная")
4. По количеству совпадений определяется оценка:

| Совпадений | Оценка |
|-----------|--------|
| 0 | 5.0 (нейтрально) |
| 1 | 6.5 (выше нейтрального) |
| 2 | 7.5 (хорошо) |
| 3-5 | 9.0 (очень хорошо) |
| 6+ | 10.0 (отлично) |

**Для критериев без ключевых слов** (например, `salary_fix`, `hh_rating`, `company_age`): даётся **5.5** (небольшой benefit of the doubt, без завышения).

#### 4.6.3. Как считается группа

```python
группа_сырая = сумма(оценка_критерия * вес_критерия)   # взвешенная сумма
группа_макс  = сумма(10 * вес_критерия)                 # если все 10
группа_оценка = группа_сырая / группа_макс * 10        # нормализация в 0-10
```

#### 4.6.4. Как считается финальный балл

```python
финал = сумма(группа_оценка * вес_группы) / сумма(вес_группы * 10) * 10
```

Без растяжения — финальный балл честно отражает средневзвешенное групп.

### 4.7. Шаг 4: Категория

| Балл | Категория | Рекомендация | Значение |
|------|-----------|-------------|----------|
| 8.0+ | **S** | apply_now | Идеально — откликаться немедленно |
| 7.0-7.99 | **A** | apply | Хорошо — откликаться |
| 6.0-6.99 | **B** | apply_caution | Средне — откликнуться с оговорками |
| 5.0-5.99 | **C** | skip | Ниже среднего — пропустить |
| <5.0 или Gate fail | **REJECT** | skip | Не подходит |

### 4.8. Риски (risks)

Для каждой вакансии генерируется до 10 рисков:
- 🔴 Fail Gate A — что именно не прошло
- 🟡 Критерии с оценкой < 4.0 — слабые места
- 🟢 Критерии с оценкой ≥ 8.0 — сильные стороны

Отображаются в UI на карточке вакансии.

## 5. Конфигурационные файлы

### 5.1. config/matrix.yaml

**Единственный источник scoring-ключевых слов.** Содержит 7 групп, ~30 критериев, ~230 ключевых слов.

**Когда менять:** Если нужно:
- Добавить ключевые слова для лучшего совпадения
- Изменить веса групп/критериев (влияет на итоговый балл)
- Убрать/добавить критерий

**Как влияет:** Изменение keywords меняет оценку соответствующих критериев. Изменение weight меняет вклад группы в итоговый балл.

### 5.2. config/ues_config.json

Содержит **настройки блоков** (красные флаги) и **настройки Gate A/B** (пороги зарплат, архетипы).

**Когда менять:** Если нужно:
- Добавить новый блок (например, "не рассматриваем стартапы")
- Изменить пороги ЗП (min_pass, target)
- Изменить ключевые слова архетипов (Gate B)
- Редактировать проще в JSON, но можно и через код (DEFAULT_UES_CONFIG — fallback)

### 5.3. config/profile.json

Содержит **фильтры для сканера** и **ключевые слова резюме**:

- `search_filters` — параметры поиска HH (регионы, заголовки, ЗП, опыт)
- `resume_data.keywords` — ключевые слова из резюме (для Gate B)

## 6. Что было пофикшено в этой сессии (27-28.06.2026)

### 6.1. Критический баг: регион в сканере
**Проблема:** В profile.json был ключ `"area": 113`, но scanner.py читал `regions`. Фильтр регионов игнорировался, сканер искал по умолчанию.
**Фикс:** profile.json переведён на `"regions": ["Россия"]`, `_resolve_areas()` маппит "Россия" → "113".

### 6.2. Баг: удалёнка Gate A не находилась из-за ё/е
**Проблема:** В тексте "удаленная работа" (с е), а ключевое слово "удалён" (с ё). `str.find()` не считает их одинаковыми.
**Фикс:** Добавлена нормализация `ё → е` и в текст вакансии, и во все проверяемые ключевые слова (Gate A, Blocks, keyword matching).

### 6.3. Scoring переключён с kw_map на matrix.yaml
**Было:** Жёстко зашитый словарь `kw_map` в коде ues.py с ~15 критериями и ~50 ключевыми словами.
**Стало:** Чтение `config/matrix.yaml` — 7 групп, ~30 критериев, ~230 ключевых слов. Единый источник правды.
**Зачем:** matrix.yaml можно редактировать без изменения кода. Ключевые слова разложены по критериям, а не плоским списком.

### 6.4. Удалён мёртвый код
Из ues.py удалён старый метод `_rate_criterion()` (использовал kw_map, не вызывался последние недели). -50 строк.

### 6.5. Добавлены блоки (красные флаги)
Три блока: гемблинг, не-PM-роли, gamedev. Проверяются до Gate A/B. При совпадении — REJECT с score=0.

### 6.6. Override адаптирован под новую систему
**Было:** Проверял group_id="company", group_id="personal_fit", criterion_id="driver_alignment" — эти ID не существуют в matrix.yaml.
**Стало:** Проверяет group="company" + avg("role", "tech", "culture").

### 6.7. Zero-keyword критерии (калибровка)
**Было:** Zero-keyword критерии (salary_fix, hh_rating, company_age, ceo_media) получали 7.0. Неизвестный стартап получал балл как у Сбера — нечестно.
**Стало:** 5.5 — небольшой benefit of the doubt без завышения.

### 6.8. Multi-word fallback
Если фраза "удаленная работа" не совпала целиком, проверяются отдельные слова:
- "удаленная" встречается в тексте?
- "работа" встречается в тексте?
- Если оба да → засчитывается как совпадение.

## 8. Где и как влиять на оценку

### Хотите изменить вес групп?
→ Править `config/matrix.yaml` → weight у группы.

Пример: увеличить вес `tech` с 7 до 9, чтобы вакансии с BI/DWH стеком получали выше балл.

### Хотите добавить ключевые слова?
→ Править `config/matrix.yaml` → keywords у критерия.

Пример: добавить "delivery lead" в `pm_po_hybrid`, чтобы лучше ловить такие вакансии.

### Хотите изменить пороги Gate A?
→ Править `config/ues_config.json` → gates → gate_a → salary → min_pass/target.

### Хотите добавить блок (красный флаг)?
→ Править `config/ues_config.json` → blocks.

Пример: добавить блок "стартапы < 20 человек" с ключевыми словами "startup", "стартап".

### Хотите изменить архетипы Gate B?
→ Править `config/ues_config.json` → gates → gate_b → keywords.

### Хотите изменить кривую оценки (match→score)?
→ Править `_rate_criterion_keywords()` в `src/ues.py`.

### Хотите изменить растяжение финального балла?
→ Править `_compute_final()` в `src/ues.py`.

### Хотите перепроверить все вакансии?
→ Запустить скрипт batch_reeval.py (лежит в Temp если есть).

## 10. TL;DR для HR (одним абзацем)

Система парсит HH.ru, прогоняет каждую вакансию через 4 фильтра: (0) красные флаги — гемблинг/не-PM/геймдев → сразу нет, (1) удалёнка/ЗП/локация — базовый отсев, (2) роль PM/PO — профпригодность, (3) оценка по 7 группам из matrix.yaml — взвешенная сумма 30 критериев по ~230 ключевым словам. Если базовый отсев не прошёл, но вакансия объективно сильная — срабатывает Override. Итог: категория S/A/B/C/REJECT с конкретным баллом и списком рисков. Все настройки в трёх конфигах, код можно не трогать.
