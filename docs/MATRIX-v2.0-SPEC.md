## 1. Архитектура скоринга (двухуровневая)

```
Финальный балл = Σ(вес_группы / Σ_всех_весов_групп × скор_группы)
скор_группы = Σ(вес_критерия / Σ_весов_критериев_в_группе × оценка_критерия)
оценка_критерия = match_curve[количество_совпадений_ключевых_слов]
```

- Вес группы — влияние группы на финал (из 68)
- Вес критерия — влияние критерия внутри группы
- Оба уровня независимы: изменение веса критерия не меняет вес группы

---

## 2. Параметры скоринга (scoring)

```yaml
scoring:
  match_curve:
    - {matches: 0, score: 5.0}    # Нет совпадений — нейтрально, не штраф
    - {matches: 1, score: 6.0}    # Слабое совпадение
    - {matches: 2, score: 7.0}    # Умеренное совпадение
    - {matches: 3, score: 8.0}    # Хорошее совпадение
    - {matches: 4, score: 9.0}    # Отличное совпадение (4+)
  zero_keyword_default: 5.0       # Если у критерия пустой список keywords
  stretch:
    enabled: false                # Отключено — не растягиваем баллы
  classify:
    - {min_score: 8.0, category: "S", recommendation: "apply_now"}
    - {min_score: 7.0, category: "A", recommendation: "apply"}
    - {min_score: 6.0, category: "B", recommendation: "apply_caution"}
    - {min_score: 5.0, category: "C", recommendation: "skip"}
```

## 5. Gate'ы

### 5.1 Gate A — Жёсткие фильтры

```yaml
gates:
  gate_a:
    remote:
      pass: ["remote", "hybrid"]
      fail: ["office"]
      logic: "Если текст содержит 'office'-ключи и не содержит 'remote'-ключи → fail"
    salary:
      min_pass: 200000       # минимальный проходной порог
      target: 250000         # желаемый уровень (при нём балл не снижается)
      net_gross_logic: true  # см. раздел 5.3
    location:
      pass: ["msk", "spb", "remote"]
```

### 5.2 Gate B — Проверка архетипа резюме

```yaml
  gate_b:
    archetype_01:    # Enterprise PM
      match_mode: word       # целые слова, не подстроки
      keywords:
        - project manager, delivery manager, program manager,
          руководитель проектов, менеджер проектов, pmo,
          управление проектами, руководитель портфеля,
          портфель проектов, it project manager
    archetype_03:    # Hybrid PM-PO
      match_mode: word
      keywords:
        - product manager, product owner, po,
          продуктовый менеджер, владелец продукта,
          продукт-менеджер, pm/po, hybrid pm,
          управление продуктом, менеджер продукта
```

> **Важно:** Gate B должен проверять целые биграммы («руководитель проектов»), а не вхождение одиночных слов («руководитель» в «руководитель отдела продаж»).

### 5.3 Salary net/gross — предобработка

Перед сравнением с порогом 250k net:

1. Извлечь числовое значение зарплаты из текста вакансии
2. Определить модификатор:
   - *gross / до вычета / до уплаты налогов / до вычета налогов* → сумма × 0.87 (net)
   - *net / на руки / чистыми* → сумма как есть
   - Не определено → считать gross (консервативно)
3. Сравнить полученную net-сумму с `min_pass` и `target`

## 6. Механизм Weight = 0 («неважно»)

Если вес критерия = 0:

1. **Критерий исключается** из поиска ключевых слов (не сканируется)
2. **Исключается из суммы весов** внутри группы (не искажает доли других критериев)
3. **Не участвует** в расчёте группового скора
4. **Не отображается** в отчёте/анализе как «проваленный»
5. В UI: серый/неактивный, подпись «неважно»

Если вес группы = 0:

1. **Группа целиком исключается** из финального скора
2. **Исключается из суммы весов групп** (знаменатель 68 уменьшается)
3. В UI: группа свёрнута/серая, подпись «неважно»

### Пример

Пользователь ставит `exp_wms.weight = 0`. Группа 4a (Отраслевой опыт) имеет критерии с весами [9, 10, 0, 8]. Эффективная сумма = 27 (а не 27+0). Критерий WMS не ищется и не считается. Доли остальных: 9/27, 10/27, 8/27.

## 7. Override (High Potential)

Если Gate A не пройден, но:

- Gate B пройден (роль совпадает)
- Общий балл (Company Fit + Role/Tech/Culture) ≥ 6.5

→ Gate A принудительно пропускается. Вакансия получает полный скоринг, рекомендация `apply_terms` (отклик на своих условиях).
