# Как я как IT-Project Manager автоматизировал собственный поиск работы: опыт создания ValueHunt

*Публикация для Habr / VC.ru. Рассказ о том, почему менеджер проектов вместо «просто откликаться» написал собственный инструмент скоринга вакансий, CRM контактов и аналитики воронки.*

---

## Проблема: поиск работы — это тоже проект

Когда поиск работы становится системной задачей — 100+ откликов, десятки собеседований, переписка с HR из разных компаний — ты быстро замечаешь: **всё это плохо управляется** «в голове» и в таблицах.

Типичные симптомы:

- Откликнулся на вакансию, а через неделю не помнишь, о чём там было и на каком этапе процесс;
- Компании, которые кажутся похожими, на поверку сильно отличаются — по условиям, культуре, стеку. А мы сравниваем их «на глаз»;
- Контакты HR разбросаны по мессенджерам, почте и Excel — теряются, дублируются, забываются;
- Нет понимания, где именно «теряется» воронка: мало откликов? Слабый отклик? Долгие ответы?

Я — IT Project Manager с 20-летним опытом (промышленное строительство, потом системная интеграция: DWH/BI, WMS). Моя работа — превращать хаос в управляемый процесс. Поэтому я решил применить тот же подход к собственному поиску работы: **построил систему**.

Так появился **ValueHunt** — локальный open-source инструмент, который собирает вакансии с HeadHunter, оценивает их по личной матрице ценностей и помогает вести воронку откликов.

---

## Идея: «скоринг» вместо «глазами»

Вместо того чтобы читать каждую вакансию в поисках «что-то знакомое», я формализовал критерии, которые важны лично мне, и превратил их в **матрицу скоринга**.

### Как устроен скоринг (UES — Universal Evaluation Score)

Матрица состоит из групп и критериев. Каждый критерий имеет вес и набор ключевых слов. Группы:

| Группа | Что оценивает |
|---|---|
| **Роль и содержание** | PM/PO-функции, Enterprise-масштаб, продуктовое влияние |
| **Условия работы** | удалёнка, гибрид, локация, гибкий график |
| **Финансы** | вилка ЗП, IT-аккредитация, ДМС |
| **Отраслевой опыт** | B2B/B2G, DWH/BI, WMS, PMO |
| **Отраслевой интерес** | Geo, AI, Fintech, MedTech |
| **Компания и репутация** | отзывы, возраст, зрелость HR |
| **Карьера и развитие** | грейды, обучение, менторство |
| **Технологический стек** | современный стек, Data, AI, продуктовые метрики |
| **Культура и процессы** | Agile, прозрачность, прямой найм, соцпакет |

Плюс — **Gates** (шлюзы): вакансия, не прошедшая базовые фильтры (не PM/PO-роль, гемблинг, game-dev и т.п.), отсекается до скоринга. Это экономит время: ты не тратишь минуты на заведомо неподходящее.

Результат — **категория вакансии**:

- **S (8.0+)** — «идеально», откликаться в первую очередь
- **A (7.0+)** — «отлично»
- **B (6.0+)** — «хорошо», с оговорками
- **C (5.0+)** — «возможно»
- **REJECT (<5.0)** — пропустить

Матрица полностью настраивается: это YAML-файл, который можно адаптировать под любого кандидата — не только IT-менеджера.

## Архитектура

Минималистичная, без внешних сервисов и БД-серверов:

```
ValueHunt/
├── src/
│   ├── scanner.py          # парсинг HH.ru (BeautifulSoup)
│   ├── ues.py              # UES Calculator — скоринг
│   ├── collector.py        # данные о компаниях (HH + поиск + сайт)
│   ├── gate_check.py       # Gates A/B
│   ├── db.py               # SQLite — схемы, миграции, CRUD
│   └── web/                # FastAPI + Jinja2 + JS
│       ├── app.py          # API и маршруты
│       ├── templates/      # HTML-страницы
│       └── static/         # стили и скрипты
├── config/                 # profile.json, matrix.yaml, ues_config.json
├── data/                   # valuehunt.db (SQLite, создаётся автоматически)
└── docs/                   # документация: USER, ADMIN, DEV, SPEC
```

**Стек**: Python 3.12, FastAPI, SQLite, BeautifulSoup + lxml, Jinja2, PyInstaller.

**Ключевое решение** — всё локально и офлайн:

- никакого облака — данные не покидают машину;
- SQLite вместо сервера БД — переносимый файл;
- готовый `.exe` через PyInstaller — запуск без установки Python.

## Что умеет продукт

### 1. Сканер вакансий

`scanner.py` обходит HH.ru, собирает новые вакансии по заданным фильтрам (регионы, роли, ЗП, формат) и кладёт их в БД. При первом запуске поднимает историю публикаций — удобно для аналитики «сколько нового появляется в день».

### 2. UES Calculator

Каждая вакансия автоматически получает балл и категорию. Прозрачно: ты всегда можешь посмотреть, **почему** именно такой балл — какие критерии совпали, какие нет.

### 3. Дашборд

- воронка отклика: Новые → Отклик → Приглашение → В работе → Оффер → Отказ;
- распределение по категориям S/A/B/C;
- динамика публикаций по датам;
- средний балл, счётчики.

### 4. CRM контактов + календарь взаимодействий

HR-контакты с приоритетами (S/A/B/C), история переписок и звонков, запланированные действия. Дашборд «Что нужно сделать сегодня» — ничего не забывается.

### 5. Сбор данных о компаниях

Парсинг рейтингов, отзывов и стека по каждой компании — чтобы сравнивать работодателей не «по ощущениям».

### 6. Drop-out scoring

Важный нюанс скоринга: критерии, которые **не упомянуты** в вакансии, не штрафуют балл. Если в вакансии не написано про ДМС — это не значит, что компания плохая. Поэтому пустые критерии «выпадают» из расчёта, и балл отражает только то, что реально известно. Это подняло потолок оценок с 6.3 до 7.65 и сделало скоринг честным.

## Что я вынес из процесса

### Поиск работы — это конвейер, и его нужно мерить

Как только воронка стала видимой, сразу нашлись узкие места. Например, выяснилось, что много времени уходит на вакансии, которые даже не проходят по базовым критериям — их отсекли Gates.

### Прозрачность оценки важнее самой оценки

Спор «эта вакансия хорошая или нет?» заменился вопросом «какие критерии не совпали?». Это снимает эмоции и делает решение рациональным.

### Инструмент живёт итерациями

Проект развивался от простого скорера до полноценного CRM с дашбордом. Каждая новая версия — это ответ на конкретную боль в собственном процессе:

- появились контакты — потому что HR начали теряться;
- появился календарь — потому что договорённости забывались;
- появился drop-out scoring — потому что честные баллы важнее «красивых»;
- появилась сборка `.exe` — чтобы не возиться с окружением.

### Данные — это актив

Даже после закрытия поиска инструмент не бесполезен: в нём остаётся статистика «сколько откликов → сколько собеседований → сколько офферов», которую полезно пересматривать перед следующим поиском.

## Технические детали, которыми стоит поделиться

### Парсинг HH.ru без API-ключа

HH закрыл публичный API в конце 2025-го. Решение — парсинг страниц через BeautifulSoup. Это хрупко (верстка меняется), но для локального личного инструмента — достаточно. Код спроектирован так, чтобы селекторы были изолированы в одном месте и легко обновлялись.

### Миграции БД — боль, которую стоит решать структурно

SQLite-схема эволюционировала: добавлялись колонки, пересоздавались таблицы. Именно тут вскрылся классический баг: миграция, пересоздающая таблицу `interactions` через временную `interactions_v2`, теряла колонку `completed_at`, добавленную более ранней миграцией. На свежей БД всё падало с `no such column`.

**Урок**: порядок миграций и их идемпотентность — это не «потом починим». Тестируй миграции не только на «старой» БД, но и на «свежей» — с нуля.

### Frozen mode в PyInstaller

При сборке `.exe` пути к ресурсам ломаются: `__file__` указывает внутрь `_internal`. Решение — проверка `sys.frozen`:

```python
if getattr(sys, 'frozen', False):
    MEIPASS = Path(sys._MEIPASS)              # шаблоны, статика
    EXE_DIR = Path(sys.executable).resolve().parent  # config/, data/
    CONFIG_DIR = EXE_DIR / "config"
else:
    CONFIG_DIR = BASE_DIR / "config"
```

Конфиги и БД лежат **рядом с exe** — программа переносится простым копированием папки.

## Вместо заключения

ValueHunt — это пример того, как **инструмент, написанный для решения личной задачи**, превращается в законченный продукт с документацией, сборкой и релизами. Мне как PM было важно не просто «написать код», а выстроить процесс: от идеи через скоринг к аналитике воронки.

Если вы ищете работу в IT и чувствуете, что «процесс неуправляем» — возможно, стоит не просто откликаться активнее, а сначала сделать воронку видимой.
