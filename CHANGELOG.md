# Changelog — ValueHunt

Формат версий: **Глобальная.Фича.Багфикс**

- **Глобальная** — архитектурные перестройки, смена БД, полный редизайн
- **Фича** — крупные возможности (мульти-профиль, дашборд, сканер)
- **Багфикс** — исправления, мелкие доработки, косметика

---

## 1.14.0 — Готовая сборка + Адаптивный скоринг (2026-07-24)

### Добавлено
- **PyInstaller сборка**: `ValueHunt.exe` — один файл для запуска, без Python и .bat
- **Авто-копирование конфигов**: при первом запуске exe создаёт `config/` и `data/` рядом с собой
- **Frozen mode**: коррекция путей для работы в PyInstaller-сборке (app.py, db.py, ues.py)

### Архитектурные решения
- **Адаптивная матрица скоринга**: LLM-агент динамически оценивает вакансии вместо жёстких keywords
- **Drop-out scoring**: критерии без совпадений не штрафуют, а выпадают из расчёта
- **База данных**: data/ лежит рядом с exe, переносится вместе с программой

### Исправлено
- `init_db()`: при создании свежей БД миграция interactions_v2 падала из-за лишней колонки `completed_at` — исправлено явным перечислением колонок в INSERT

## 0.3.0 — Soft Delete + Выпадение пустых критериев (2026-06-28)

### Добавлено
- **Soft Delete (корзина)**: вакансии помечаются `deleted_at` вместо удаления из БД
- **Страница `/trash`**: список удалённых с причиной, датой, баллом, кнопками восстановления и безвозвратного удаления
- **Кнопка «🗑 Удалить»** в карточке вакансии с модалкой выбора причины (6 вариантов)
- **Статистика корзины** на дашборде (`trash.total`, `trash.by_reason`)
- **Счётчик в боковом меню**: «🗑 Корзина (N)»
- **API эндпоинты**: `POST /api/vacancies/{id}/trash`, `POST /api/vacancies/{id}/restore`, `DELETE /api/vacancies/{id}`, `GET /api/trash`, `GET /api/trash-stats`
- **Логика выпадения пустых критериев**: критерии с keywords и 0 совпадений не участвуют в скоринге (не штрафуют). Защита: <6 активных → fallback на старую логику

### Изменено
- `UESCalculator._score_groups()` — режим drop-out для 0-match критериев (подняло потолок с 6.3 до 7.65)
- `UESCalculator.__init__()` — читает `ues_config.json` вместо `DEFAULT_UES_CONFIG` (починило калибровку match_curve)
- Все 18 SELECT-запросов к `vacancies` фильтруют `WHERE deleted_at IS NULL`
- Схема БД: добавлены колонки `deleted_at TEXT`, `delete_reason TEXT`

### Исправлено
- `PRAGMA table_info` использовал `d[0]` (cid) вместо `d[1]` (name) — сломанный reevaluate
- `UESCalculator` игнорировал файл `ues_config.json` — калибровка match_curve не применялась

## 1.13.0 — Контактная база и единый скоринг (2026-06-22)

### Добавлено
- **Таблица `contacts`**: name, role, source (HH/Telegram/LinkedIn/рекомендация/VK/email), priority (S/A/B/C), telegram, email, phone, vk, linkedin, notes, company_id → FK companies
- **Таблица `interactions`**: contact_id, vacancy_id, type, direction, summary, outcome, next_action_date
- **CRUD API**: `/api/contacts`, `/api/contacts/{id}`, `/api/interactions`
- **Страница `/contacts`**: таблица с фильтрацией по приоритету/источнику, модалка просмотра/редактирования, история взаимодействий, блок просроченных действий
- **Ссылка «Контакты»** в навигации
- **VacancyGateCheck** (`src/gate_check.py`): тонкая обёртка для Gate A/B (20 строк)
- **UESCalculator → matrix.yaml**: приоритетная загрузка keywords из `matrix.yaml`, fallback на хардкод
- **CHECK constraint на `vacancies.status`**: триггеры `trg_vacancies_status_check` + `trg_vacancies_status_update`
- **Поле `llm_generated INTEGER`** в vacancies (для будущего LLM cover letter)
- **Поле `llm_analysis TEXT`** в vacancies (ранее отсутствовал в схеме)
- **Скрипт импорта** `scripts/import_contacts.py`: парсинг contacts.md → SQLite (19 контактов, 97 взаимодействий)

### Изменено
- `UESCalculator._rate_criterion()` — keywords из `matrix.yaml` имеют приоритет над хардкодом

### Исправлено
- Порядок роутов в FastAPI: `/api/contacts/due-for-action` больше не перехватывается `{contact_id}`
- Парсер contacts.md: фильтрация мусорных строк `-----`

## 1.12.0 — Мульти-профили (2026-06-21)

### Добавлено
- Система профилей: создание, переключение, редактирование, удаление
- Связь «вакансия ↔ профиль» через таблицу `vacancy_profiles` (many-to-many)
- CRUD API для профилей (`/api/profiles`)
- Редизайн страницы Профиля: список профилей + редактор
- Фильтр по профилю на Дашборде (данные пересчитываются при смене)
- Сканер привязан к профилю: `/api/scan?profile_id=N`
- Датаграфик с переключателем 7/14/30 дней / Всё время + календарь
- Датаграфик: stacked bars по категориям (S/A/B/C) и по статусам
- Воронка отклика с прогресс-барами вместо плоского списка
- Фильтр периода на странице Вакансий (сутки/неделя/месяц/произвольный)
- Счётчик «Найдено вакансий: X» над таблицей
- Кликабельные ссылки на цифрах категорий в кольцевой диаграмме
- `INSERT OR IGNORE` — дубли не перезаписываются, а пропускаются
- Подпись на датаграфике: «даты публикации на hh.ru, не даты сканирования»

### Изменено
- Категория REJECT переименована в «Пропустить»
- Полные названия категорий: «Идеально (8.0+)», «Отлично (7.0+)» и т.д.
- Формат дат на графиках: ДД.ММ.ГГ
- Сообщение сканера теперь показывает: «HH.ru показал X. Добавлено в БД: Y, уже были: Z. Всего в БД: W»

### Исправлено
- Старый `loadVacancies()` из app.js перетирал новую таблицу вакансий — удалён
- `INSERT OR REPLACE` заменён на `INSERT OR IGNORE` — корректный подсчёт новых
- Конфликт имён `save_profile` (profile.json vs db.profiles) — исправлен
